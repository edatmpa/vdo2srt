## Running the tool

```powershell

# Batch (pass a folder instead of a file)
"E:\Plex Utility\vdo2srt\venv\Scripts\python.exe" vdo2srt.py "E:\Movies" --engine local --language ru

# Skip English translation
"E:\Plex Utility\vdo2srt\venv\Scripts\python.exe" vdo2srt.py "E:\Movies" --engine local --language ru --no-translate

# Run as a module (alternative entry point)
"E:\Plex Utility\vdo2srt\venv\Scripts\python.exe" -m src "E:\path\to\film.mkv" --engine local --language ru

# Batch over many folders from a list file (e.g. a "no subs" export)
"E:\Plex Utility\vdo2srt\venv\Scripts\python.exe" process_list.py "E:\no_subs.txt" --engine local --language ru

# Translate existing .srt files only — no video, no transcription
"E:\Plex Utility\vdo2srt\venv\Scripts\python.exe" translate_srt.py "V:\War Series (Russia)" --recursive
```

Key CLI flags (`vdo2srt.py` / `process_list.py`): `--engine local|cloud`, `--model tiny|base|small|medium|large-v2|large-v3` (default: large-v3), `--device auto|cuda|cpu`, `--language LANG`, `--max-duration SECS` (default: 6, 0=off), `--no-translate`, `--target-language LANG` (default: en), `--overwrite` (batch mode — see below for exactly what this re-does).

`translate_srt.py` flags: `--recursive`, `--target-language LANG` (default: en), `--overwrite`.

Install dependencies: run `setup.bat` (builds/repairs the venv for this PC — see "Environment, launchers and setup").

## Architecture

**Entry points:**
- `vdo2srt.py` (root) — thin wrapper delegating to `src/cli.py`; single file or one folder.
- `process_list.py` (root) — batch over many folders read from a plain-text list file (one path per line; the list itself is generated by the user's own separate tooling — not this project's concern).
- `translate_srt.py` (root) — translates existing `.srt` files with **no video/transcription involved at all**; single file, one folder, or (with `--recursive`) a library root scanned one level down into its immediate movie/show subfolders.

The `src/` package contains all shared application logic.

**Package structure:**
```
src/
├── __init__.py      Package marker, version string
├── __main__.py      Entry point for `python -m src`
├── cli.py           vdo2srt.py's CLI — argument parsing, orchestration, batch/single-file routing
├── gui.py           Tkinter GUI dialogs — file/folder picker, method picker
├── extractor.py     FFmpeg wrapper — audio extraction and chunking
├── transcriber.py   Transcription engines — faster-whisper (local) and Google STT (cloud)
├── translator.py    Translation engines (DeepL / free fallback), per-language routing, translate_existing_srt()
├── srt_reader.py    Parses an existing .srt file back into segment dicts
├── srt_writer.py    SRT formatter — converts segments to subtitle file
└── utils.py         Shared constants/helpers: find_media_files, find_original_srt_files,
                      find_movie_subfolders, is_skippable_folder, backup_if_exists, clean_path
```

**Pipeline** (single file, via `vdo2srt.py`):
1. `extractor.extract_audio()` — FFmpeg extracts 16kHz mono WAV to `%TEMP%\vdo2srt\`
2. `transcriber.get_transcriber()` returns either `LocalTranscriber` or `CloudTranscriber`
3. `transcriber.transcribe()` returns `list[dict]` with `{start, end, text}` keys
4. `srt_writer.write_srt()` writes the `.srt` file
5. `translator.translate_segments()` translates and writes the `.en.srt` (unless `--no-translate`)

**`src/transcriber.py`** — Two engines:
- `LocalTranscriber`: faster-whisper on CUDA (int8_float16) or CPU (int8). Auto-detects GPU via ctranslate2. If `max_duration` is set, requests `word_timestamps=True` from Whisper and then calls `split_segments()` to re-cut long entries at word boundaries.
- `CloudTranscriber`: chunks audio into 55-second slices (under the 60s sync API limit), sends each to Google STT, reassembles with corrected timestamps. Language must be BCP-47; a short mapping dict handles `ru`→`ru-RU` etc.

**`src/translator.py`** — pluggable engines, routed per *detected* source language (not `--language`/Whisper's guess — real per-file text detection, since translate-only paths often have no language metadata at all):
- `detect_source_language(segments)` — `langdetect` on a concatenated sample of the first ~30 non-empty segments (single subtitle lines are too short to detect reliably alone). Normalizes langdetect's `zh-cn`/`zh-tw` → `zh`.
- `translate_routing.txt` (repo root) maps a detected language to an engine + key file — currently `ko`/`ja`/`zh`/`ru` → `DeepLEngine` + `E:\API Key\Key files\platform\deepl.saksiri.txt` (2-line key format, see below). Any language **not** listed falls back to `GoogleEngine` (free, keyless, via `deep-translator`) automatically. **To route a new language to a better engine later, or move one to a different key, edit that file — no code change.** A genuinely new engine *type* needs one new class in `translator.py` plus one entry in the `_ENGINES` registry.
- `get_translator(source_lang)` resolves and caches an engine instance per the routing table, degrading gracefully to the free fallback (with a printed note) if a routed key file is missing or the `deepl` package isn't installed — never hard-crashes a batch run over a config problem.
- `translate_segments(segments, target_lang, source_lang=None)` — the shared public entry point (batches of 20; DeepL translates a whole batch in one call, the free engine still uses the `" ||| "`-join trick since `deep-translator`'s API is one-string-at-a-time). Retries up to 3 times (2 s, 4 s, 8 s backoff) on any error.
- `translate_existing_srt(srt_path, target_lang, overwrite=False)` — reads an existing `.srt` (`srt_reader.read_srt`), translates, writes `<stem>.<target_lang>.srt`. Skipped if that file already exists, unless `overwrite=True` — in which case the previous translation is backed up to `<name>.srt.bak` (`utils.backup_if_exists`) before being replaced. This one function is the shared workhorse behind `cli.py`'s translate-only path, `process_list.py`, and `translate_srt.py` — deliberately kept independent of `cli.py`/`transcriber.py` so `translate_srt.py` never pulls in faster-whisper just to do a text-to-text translation.

**Segment dict shape:** `{start: float, end: float, text: str}`. The `words` key (list of faster-whisper Word objects) is present only during local transcription when `max_duration` is set; it is stripped by `split_segments()` before segments leave `transcriber.py`.

## Batch modes and the translate-only path

**The invariant that matters across all three entry points: voice-to-text never re-runs on a video that already has its original-language `.srt`.** Only genuinely new videos (no `.srt` yet) go through the full transcribe pipeline; everything else is translation-only.

- **`cli.py` folder mode** splits work into `to_transcribe` (no `.srt` yet), `to_translate_only` (media file's `.srt` already exists), and **orphan `.srt`s** — original `.srt` files found via `utils.find_original_srt_files()` that have no matching media file at all in that folder (the video was moved/deleted after transcription). All three are handled in one pass over one folder.
- **`process_list.py`** applies the exact same three-way split per folder, across every folder listed in the input `.txt` file (numbered or plain lines; hidden/junk folder names like `Extras`/`Featurettes` are skipped via `utils.is_skippable_folder`). This was the actual gap that motivated the split — previously it only ever transcribed, silently skipping any folder whose video already had a `.srt`, never translating it.
- **`translate_srt.py`** is the pure text-to-text tool for when there's no upstream "list of folders needing translation" generator (unlike the "no subs" list, which is the user's own separate tooling — not duplicated here). Given a library root, `--recursive` walks exactly one level down into movie/show subfolders (`utils.find_movie_subfolders`) — matching the real library shape (`root → movie folders → video + srt files`), not an arbitrary-depth walk.
- **`--overwrite`** means "redo the work even though output already exists," scoped to whichever stage applies: for a video with an existing `.srt`, it forces a full re-transcribe (existing, unchanged behavior); for anything going through `translate_existing_srt` (translate-only files, orphans, or `translate_srt.py`), it forces a retranslation, backing up the previous `.en.srt` to `.bak` first.
- **"Original" vs. "already a translation"**: `find_original_srt_files()` excludes any `.srt` whose filename ends in a language-code-shaped suffix (`movie.en.srt`, `movie.zh-cn.srt`) before matching — a 3+ letter release tag like `Holod.S01E01.AVC.srt` never collides with this.

## API key file format

Third-party API keys (e.g. DeepL) are stored as plain `.txt` files under `E:\API Key\Key files\<group>\`, managed by the separate API Key Checker project at `E:\API Key\`. When given a path to one of these files, read it as:

- **Line 1** — the API secret/token. Nothing else on the line.
- **Line 2** — the API endpoint URL (optional; omit or blank if the SDK/library has its own default endpoint).
- Any further lines are unused.

Example — `deepl.saksiri.txt`:
```
<the-deepl-api-key>
https://api-free.deepl.com
```

Read the secret with a simple two-line file read (strip whitespace); do not treat the file as JSON or key=value config. This is the same format the API Key Checker tool (`E:\API Key\scripts\config.py`) expects for all `.txt` key files, so don't invent a different parsing convention here.
